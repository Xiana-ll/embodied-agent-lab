## 一、训练阶段（2026 年 7 月）


### 1.1 数据版本不匹配

**现象**：旧版数据集配新代码，训练时字段对不上。

**原因**：MiniMind 迭代快，`mini` 版数据格式和代码版本强绑定。

**解决**：确认使用 MiniMind-3 对应版本的数据集，重新下载。

**教训**：代码和数据的版本永远成对升级。


### 1.2 Python 依赖冲突

**现象**：按 `requirements.txt` 固定版本安装后，torch 与其他包冲突，装完起不来。

**原因**：版本锁是作者环境的快照，和云端镜像的 CUDA / Python 版本对不上。

**解决**：去掉版本锁，只保留包名，让 pip 自行解析。

## 二、自己写代码跑 Agent（2026 年 11 月）


### 2.1 每次运行都要重新加载模型

**现象**：改一行代码点一次运行，每次都要等十几秒才开始出结果。

**原因**：脚本模式是「从头执行整个文件」。读 128MB 权重、初始化、搬上显存，每次都得重来；生成那部分只占一秒左右，九成时间花在加载上。

**解决**：学习中先忍；真要反复调，就改成一次加载、循环跑多个问题。

**教训**：同一段加载代码，写在函数外（模块级）就是服务，写在脚本里就是一次性任务。位置决定它是哪种东西。


### 2.2 贪心解码下模型整段复读

**现象**：`do_sample=False` 时，回答完还要把同一句再重复一遍：

```
现在是2026年11月2日21时45分04秒（北京时间）。
2026年11月2日21时45分04秒（北京时间）。
```

**原因**：64M 小模型在贪心解码下容易掉进局部循环。

**解决**：演示时用 `do_sample=True, temperature=0.7` 缓解。这是能力问题，不是代码 bug。


### 2.3 换个说法，工具就调错了

**现象**：同一个问题，换个说法结果完全不同。

| 问法 | 实际调用 | 答案 | 正确 |
|---|---|---|---|
| `帮我算一下 128 乘以 5` | `get_current_time` + `calculate_math` | 640 | ✅ |
| `128乘以5是多少` | 只调 `get_current_time` | 55555 | ❌ |
| `计算 128*5` | 只调 `get_current_time` | 235 | ❌ |

**教训**：只看到「换个说法结果不同」还不够，得往下追一层才知道原因（见 3.2）。


### 2.4 10 条测试集：模型 5/10

**做法**：固定 10 条（5 条算术 / 3 条时间 / 2 条寒暄），`do_sample=False` 保证可复现，模型只加载一次，循环跑完。

**结果**：

| 实际输出 | 次数 |
|---|---|
| `get_current_time` | 8 / 10 |
| `calculate_math` | 1 / 10 |
| 不调工具 | 1 / 10 |

**正确率 5/10 = 50%。**

**但这个 50% 是假象**：10 条里有 8 条输出同一个常量。正确的那 5 条，是因为「该调时间」的题目恰好占了 4 条，撞上了它的默认输出。

**结论**：模型的输出和问题内容基本无关，它不是在选，是在复述一个高频常量。50% 这个数字不代表任何判断能力。


### 2.5 规则路由 10/10，但换个说法就漏

**做法**：不指望模型选，用正则按问题内容路由：

```python
if re.search(r"\d", q) and re.search(r"乘|除|加|减|[+\-*/]", q):
    return "calculate_math"
elif re.search(r"几|时间|日期|今天", q):
    return "get_current_time"
return None
```

**结果**：同一批 10 条，路由 10/10。

**然后补测 5 条边界样本**，其中：

```
帮我算一下 2 的 10 次方   → 路由到 None（期望 calculate_math）❌
```

因为规则里只有「乘除加减」，没有「次方」——**同一个意思换个说法，规则就不认了。**

**结论**：路由的 100% 是过拟合——测试集和规则是同一批人写的，出题人和做题人是同一个。换几个没预料到的说法就掉。

**两者都是模式匹配**，区别是：规则写什么就做什么，可查可修但补不完；模型自己猜，灵活但猜错也看不出原因。

**取舍**：采用「规则兜底 + 模型负责组织语言」，并在 README 里注明模型不具备自主选择能力。


### 2.6 双击 start_demo.bat，窗口一闪就退

**现象**：双击没反应，看不到任何错误。

**原因**：两个问题叠在一起。

1. **`.bat` 里写了中文路径**。文件是 UTF-8 存的，但 cmd 按 GBK 解析，`实验室` 被读成 `瀹為獙瀹`，`if not exist` 判断失败，退回到系统 `python`（没装 torch），直接退出。
2. **换行符是 LF 不是 CRLF**。`.bat` 必须 CRLF，否则 cmd 解析错乱，`rem One-click launcher` 被拆成两条命令：

```
'em' is not recognized as an internal or external command
'd' is not recognized as an internal or external command
```

**解决**：脚本只用 ASCII、不写中文路径；换行改 CRLF；后来把 `minimind-master` 整体搬到 `11111\minimind-master`，路径里不再有中文。

**教训**：`.bat` 的编码坑比 Python 狠——它不报错，只闪一下。脚本末尾加 `pause`，至少能看到红字。

## 三、已知边界

| 问题 | 原因 | 后续 |
|---|---|---|
| 工具选择不成立 | 模型只输出高频常量，不读工具清单 | 需重训 SFT，或规则前置 |
| 事实性幻觉 | 参数量不够存知识 | RAG 或更大模型 |
| 无流式输出 | 只做了非流式 | 加 SSE 即可 |

---

## 四、总结

1.先写冒烟测试，把「模型坏了」和「服务坏了」分开，能省掉大量瞎猜。
2.指标会骗人：50% 的正确率可能是「80% 输出同一个常量」碰巧撞对的。看到数字先问「这个数是怎么来的」。 
3.自己写的规则也会过拟合：测试集自己挑的，100% 不算数，得找没想到的写法去撞。
